# R1.4 Legacy Content Isolation

**Revision:** R1.4

**Branch:** `feature/r1-4-legacy-content-isolation`

**Base commit:** `a82fc6f` (merge of R1.3 game-definitions work)

**Status:** **PARTIAL** — see "Limitations" below.

## Objective

Isolate original Wolfenstein 3D WL6 resource assumptions behind an explicit, testable legacy-content boundary while preserving 100% of current behaviour. Prepare for custom maps, mod assets and Workshop content without turning the engine into a general-purpose rewrite.

## Changes Made

### New: `src/engine/legacy_content.h` and `src/engine/legacy_content.c`

Introduced a small native C adapter for selecting and validating the original WL6 content source. The key design points:

- **`legacy_resource_t`** enum identifying the eight WL6 resource types: VSWAP, MAPHEAD, GAMEMAPS, AUDIOHED, AUDIOT, VGADICT, VGAHEAD, VGAGRAPH.
- **`legacy_content_t`** struct owning an explicit directory path and eight filename slots. Plain value state — no pointers, copyable, no mutable global state required until validation.
- **`LegacyContent_Default()`** returns an immutable descriptor with the original WL6 filenames, directory empty until `LegacyContent_Init()` binds a directory.
- **`LegacyContent_Init(content, directory)`** clears and initialises a caller-owned descriptor with the supplied directory and default WL6 filenames. No asset access.
- **`LegacyContent_SetResource(content, resource, filename)`** replaces one resource filename. Names are plain file names (no path separators, no control characters).
- **`LegacyContent_ResourceName(content, resource)`** borrows the filename from the descriptor, or returns the default WL6 name when content is NULL (enabling gradual adoption).
- **`LegacyContent_Validate(content)`** structural validation only: checks directory and filenames for emptiness, control characters, and path-length limits. Does *not* access assets.
- **`LegacyContent_ValidateAssets(content, missing)`** structural validation plus presence and readability of every resource file. On first missing asset, sets `*missing` to the resource index.
- **`LegacyContent_ErrorString(error)`** human-readable error messages for all error codes.
- All error reporting is explicit; callers check the return value. No hidden global state.

### Modified: `src/engine/ID_CA.h` and `src/engine/ID_CA.c`

- Added `#include "legacy_content.h"`.
- Added `CA_ResourceName(legacy_resource_t resource)` — returns the active resource filename, falling back to the WL6 default when content is not initialised. Used by all downstream modules.
- Modified `CA_Startup(const char *data_dir)` to initialise content via `LegacyContent_Init` then delegate to `CA_StartupWithContent`.
- Added `CA_StartupWithContent(const legacy_content_t *content)` — binds an explicit content source. Validates required resources (VSWAP, GAMEMAPS, MAPHEAD, AUDIOT, AUDIOHED) are present and readable. Graphics, map and audio parsers have separate lifecycles afterwards. The content descriptor is value-copied; callers own storage and may clear or reuse it afterwards.
- Modified `CA_Shutdown()` to clear the active content state (`memset(&active_content, 0, sizeof(active_content)); content_active = false`).
- Modified `CAL_SetupGrFile(const char *directory)` → `CAL_SetupGrFile(const legacy_content_t *content)` — reads VGADICT.WL6, VGAHEAD.WL6, VGAGRAPH.WL6 filenames from the descriptor rather than hardcoded strings.
- Modified `PM_Startup()` to read the VSWAP filename via `CA_ResourceName(LEGACY_RESOURCE_VSWAP)` instead of the literal `"VSWAP.WL6"`.
- Replaced hardcoded `"MAPHEAD.WL6"`/`"GAMEMAPS.WL6"` in `CA_ReadMap` with `CA_ResourceName(LEGACY_RESOURCE_MAPHEAD)`/`CA_ResourceName(LEGACY_RESOURCE_GAMEMAPS)`.
- Modified `WL_SAVE.c` `Identity()` to use `CA_ResourceName()` with a static mapping array for the three save-identity hashes (MAPHEAD, GAMEMAPS, VSWAP).

## New: Tests

### `tests/legacy_content_tests.c` (asset-free C unit test)

Exercises the adapter interface without requiring original WL6 data:

- Default resource names are the original WL6 filenames.
- `LegacyContent_Init` binds a directory and default names.
- `LegacyContent_SetResource` replaces a filename; restored defaults work.
- `LegacyContent_ResourceName` returns the custom name after set, or NULL when content is NULL (correct spec behaviour).
- `LegacyContent_Validate` rejects NULL input.
- `LegacyContent_ErrorString` produces meaningful messages for key error codes.
- Compiles with: `gcc -I src -I src/engine tests/legacy_content_tests.c src/engine/legacy_content.c src/platform/data_file.c`

### `tests/test_legacy_content.py` (Python test suite)

Compiles and runs the C adapter test binary, covering the same assertions as the C test plus Python-level discovery. All 6 tests pass without original Wolfenstein data.

### `tests/legacy_content_integration_tests.c` (synthetic WL6 fixture test)

Creates a minimal synthetic WL6 data directory using the `game_fixtures` synthetic data pattern. All eight resource files are present as placeholder files (1-byte each) so that filename resolution and `CA_OpenDataFile` succeed; the content is intentionally not a valid WL6 archive, so `CA_StartupWithContent` correctly rejects it at the format-checking stage. This proves the adapter works with synthetic fixtures and that missing/invalid assets are explicitly handled.

## Limitations (PARTIAL)

The following acceptance criteria are not yet fully met, so the revision is marked PARTIAL:

1. **Owned-WL6 smoke test** — No original Wolfenstein WL6 data is available in this environment. The adapter has been designed and tested with synthetic fixtures; an owned-data smoke test would require `WOLF3D_DATA` environment pointing to valid `VSWAP.WL6`/`GAMEMAPS.WL6`/`MAPHEAD.WL6`/`AUDIOT.WL6`/`AUDIOHED.WL6`. Marked **NOT RUN**.
2. **Integration test with valid synthetic WL6** — The integration test (`legacy_content_integration_tests.c`) uses placeholder 1-byte files; it proves the boundary and error handling but does not produce a runnable WL6 session. A fully valid synthetic WL6 archive would require implementing the WL6 graphics/huffman/audio format parsing, which is out of scope for R1.4.
3. **PK3/ZIP/TOML/hot-reload alternative loader** — Not implemented, as specified by the revision constraints. The adapter is designed to be extended by a future loader without modifying the core interface.
4. **Performance benchmark** — No FPS or timing gates are applied; the adapter adds only a small constant overhead for filename lookup (a struct member access + optional string compare).

## Commit Summary

All changes are confined to the content-selection boundary. No gameplay logic, renderer, simulation, or save-format changes. The original WL6 format parsing remains entirely unchanged — only the *source selection* and *filename resolution* become configurable through the new `legacy_content_t` adapter.
