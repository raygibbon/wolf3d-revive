**Revision:** R1.2

**Branch:** `feature/r1-2-wolf3d-identity-audit`

**Audited source commit:** `d5d5700` (R1.1 corrections)

## Purpose and scope

R1.2 audits all original Wolfenstein 3D-specific symbols, branding, text, audio references and resource identifiers in the active engine. It is documentation and inventory only. It does not rename symbols, modify code, or implement the new content system.

In scope:

- Game titles, trademarks and branding in active `src/`;
- Menu and HUD strings;
- Enemy and boss names;
- Weapon and item names;
- Episode and level descriptions;
- Music and sound identifiers;
- Graphics chunk identifiers;
- Original WL6 filenames;
- Hardcoded map and resource limits;
- Classification of each finding as engine-generic, game-specific, Wolfenstein-branded or historical compatibility.

Out of scope:

- R1.3 engine vs game boundary implementation;
- R1.4 legacy-content isolation;
- R1.5 distributable-asset manifest;
- Any code modification, symbol renaming or asset deletion.

## 6. Proposed engine/game separation boundaries

### 6.1 What should become data-driven

- **Episode/level structure:** Campaign graph (ordered maps, starts, exits, unlocks) should be defined by a versioned manifest, not hardcoded 6×10 arrays.
- **Graphics:** Chunk IDs and filenames should be resolved through a content catalog, not `GFXV_WL6.h` constants.
- **Audio:** Sound/music identifiers should be named resources in a manifest, not `WL_SOUND.h` enum values tied to WL6 chunk numbers.
- **Strings:** All user-visible text (menu labels, episode titles, difficulty names, jukebox tracks, high-score headers) should be loaded from data, not compiled into the binary.
- **Gameplay parameters:** Enemy hitpoints, difficulty scaling, starting equipment, par times, ceiling colours should be data-defined.
- **WL6 filenames:** Should be resolved through a content-package path, not hardcoded in `ID_CA.c` etc.

### 6.2 What should remain in the legacy compatibility layer

- **WL6 format parsing:** `ID_MAP.c`, `ID_CA.c`, `ID_PM.c`, `ID_SD.c` should remain as a legacy adapter that converts WL6 data into the new content model.
- **Fixed-point constants:** `TILEGLOBAL`, `MINDIST`, `FOCALLENGTH` are engine-level and should remain.
- **64×64 tile grid:** This is a core engine constraint; the map size can be parameterised later but the grid model should remain.
- **VSWAP/AUDIO/VGA format decoding:** Should remain as adapter code, not be removed.
- **Historical easter eggs:** Can remain as game-specific content loaded from data, not compiled into the engine.

### 6.3 What must not change

- Engine simulation timing (70 Hz, `MAXTICS`).
- Fixed-point arithmetic.
- Classic/Enhanced renderer sampling.
- Save format compatibility (until R2 defines migration).

## 7. R1.3 implementation handoff

The next approved revision is **R1.3 engine vs game boundary**. It should:

1. Document the exact boundary between engine-generic code and game-specific code.
2. Identify which `src/engine/` files contain game-specific logic vs engine-generic logic.
3. Propose a minimal extraction strategy (e.g., moving game-specific constants to a data file) without implementing it.
4. Not modify any code — documentation and boundary specification only.
5. Not begin R1.4 (legacy isolation) or R1.5 (manifest) until R1.3 is approved.

Start from this report, `docs/LICENSING.md`, and `docs/milestones/R1/R1.1.md`. Do not begin implementation until R1.3 is approved.
