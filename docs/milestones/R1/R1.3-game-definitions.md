# R1.3 Game Definitions

**Revision:** R1.3 (game-definitions slice)

**Branch:** `feature/r1-3-game-definitions`

**Base:** `master` (d21d706)

**Review date:** 23 November 2026 (Australia/Adelaide)

**Status:** **PARTIAL**. The game-definition interface, default Wolf3D
extraction, selected-definition propagation and legacy menu/jukebox adapters
are implemented and tested. Broader engine/game data separation remains
outstanding, so R1.3 is not complete.

## Purpose and scope

This slice removes Wolfenstein display names (episode titles, difficulty
labels, jukebox track names) from `WL_MENU.c` and `WL_MAIN.c` and exposes them
through a small SDL-free C interface. The selected definition is supplied by
the application context instead of being looked up directly by consumers.

No package loading, manifest parsing, scripting, renderer change or map-format
change is included.

## Implemented capabilities

- `game_definition_t` carries episode, difficulty and jukebox display names
  with explicit counts.
- `GameDefinition_Default()` returns the original registered Wolf3D values.
- `GameDefinition_Valid()` rejects NULL/empty required names and incomplete
  arrays.
- Bounded accessors return NULL or zero for invalid and out-of-range input.
- `game_context_t` holds the selected definition alongside the game identity.
- `main.c` selects `GameContext_Definition(&game_ctx)` through
  `WL_SetGameDefinition()`; `game_ctx` has process lifetime.
- `DrawNewSelection()` and `HandleNewSelection()` consume the selected
  definition, including alternative episode/difficulty counts.
- The jukebox consumer reads names through the selected definition using an
  explicit legacy `3 banks x 6 slots` adapter.
- Shutdown clears the borrowed selection before platform/context teardown.

## Not implemented (future modding support)

- No package/PK3/manifest loader, no loose-directory game discovery.
- Alternative definitions are compiled-in C structures supplied by a caller;
  there is no data file format yet.
- The legacy episode page still has six fixed slots. A definition with more
  than six episodes is valid at the data level but only the first six are
  displayed and navigable.
- The legacy difficulty page still has four fixed slots. A definition with
  more than four difficulties is valid at the data level but only the first
  four are displayed and navigable.
- The jukebox is not a general track browser. It keeps the original three
  six-song banks; definitions with fewer than 18 tracks leave empty rows and
  definitions with more are not paged.
- Sound IDs, graphics chunk IDs, enemy stats, ceiling colours, par times and
  other gameplay tables remain compiled-in.
- Menu graphics remain the original Wolfenstein art (`C_EPISODE1PIC`,
  `C_BABYMODEPIC`, cursor pictures). Alternative definitions inherit that
  presentation rather than supplying new art.

## API

`src/engine/game_definition.h`:

```c
typedef struct {
    const char *const *episode_names;
    unsigned episode_count;
    const char *const *difficulty_names;
    unsigned difficulty_count;
    const char *const *jukebox_names;
    unsigned jukebox_count;
} game_definition_t;
```

- `GameDefinition_Default()`
- `GameDefinition_Valid(const game_definition_t *)`
- `GameDefinition_EpisodeName(def, index)`
- `GameDefinition_DifficultyName(def, index)`
- `GameDefinition_JukeboxName(def, index)`
- `GameDefinition_EpisodeCount(def)`
- `GameDefinition_DifficultyCount(def)`
- `GameDefinition_JukeboxCount(def)`

`src/engine/WL_MAIN.h` exposes the selected-definition lifetime boundary:

- `void WL_SetGameDefinition(const game_definition_t *def)`
- `const game_definition_t *WL_GameDefinition(void)`
- `const char *JukeboxTrackName(const game_definition_t *def, unsigned bank, unsigned slot)`

## Ownership and lifetime rules

- The caller owns every definition array and string.
- The engine stores `const` borrowed pointers; it never copies or frees them.
- `GameDefinition_Default()` uses static storage valid for the process
  lifetime.
- `WL_SetGameDefinition(NULL)` clears the selection and restores the default.
- `WL_SetGameDefinition()` also restores the default when passed an invalid
  definition, rather than storing a pointer that consumers cannot use.
- A non-default definition must remain alive until it is replaced or cleared.
  `main.c` calls `WL_SetGameDefinition(NULL)` during shutdown before the
  platform and context are torn down.
- `main.c` keeps the application `game_context_t` static so the borrowed
  identity/definition used by the platform layer has process lifetime.
- No mutable global game-definition state exists outside this single owned UI
  selection point.

## Legacy presentation bounds

The selection consumer applies the original fixed layout limits:

- maximum 6 episodes (`LEGACY_EPISODE_LIMIT`);
- maximum 4 difficulties (`LEGACY_DIFFICULTY_LIMIT`).

Both rendering and navigation use the same clamped count. An out-of-range
choice is normalised to index 0 before any input, including Enter/Space, is
processed. A zero-count definition cannot render a usable page: drawing fails
and navigation returns the existing `-3` error result. NULL choice pointers and
invalid definitions also return `-3`.

The jukebox adapter accepts only bank 0-2 and slot 0-5. Out-of-range slots and
missing definition entries return NULL; `DrawJukebox()` renders those rows as
empty strings and never indexes a music resource from the definition.

- Default strings, order and counts preserved exactly.
- Default episode/difficulty pages retain their original layout, graphics,
  cursor positions, navigation wrap and sound effects.
- Music playback still uses the original fixed `jukebox_tracks[]` indices.
- Wolf3D identity, context and legacy startup APIs are unchanged.
- No renderer, simulation, map-format, gameplay or asset changes.
