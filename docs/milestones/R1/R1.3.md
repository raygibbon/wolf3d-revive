## Purpose and scope

R1.3 begins implementing a clean separation between the reusable Wolf3D Revive engine and Wolfenstein-specific game logic. This document records the implementation completed in step 1 and the remaining work.

### Step 1 (complete): Game identity interface

Introduced `src/engine/game_identity.h` and `src/engine/game_identity.c` — a small, SDL-free C interface that provides game-specific metadata:

- `game_id`: unique game identifier (`"wolf3d-revive"`)
- `display_title`: window title (`"Wolf3D Revive"`)
- `prefs_id`: preferences directory name (`"wolf3d-revive"`)

The interface returns a `const game_identity_t *` to static data. Ownership is clear: the caller must not free the pointer. Lifetime is process-wide.

### Platform code updated

### Preserved behaviour

All three identity strings retain their original Wolf3D Revive values. No user-visible or filesystem-visible change occurs.

## Step 3 (complete): Application/game context

Introduced `src/engine/game_context.h` and `src/engine/game_context.c` — a small application/game context with explicit ownership:

- `game_context_t` holds a `const game_identity_t *identity`.
- `GameContext_InitDefault()` creates a context from the default identity.
- `GameContext_Init()` creates a context from a caller-supplied identity, validating required fields and filesystem safety.
- `GameContext_Identity()` returns the identity held by the context.
- `GameContext_Valid()` validates the context.

### Platform integration

| File | Change |
| --- | --- |
| `src/platform/sdl_video.h` | Added `VL_StartupWithContext()` and `VL_ScreenshotWithContext()` declarations |
| `src/platform/sdl_video.c` | `VL_Startup()` delegates to `VL_StartupWithContext()` with default context; `VL_Screenshot()` delegates to `VL_ScreenshotWithContext()` |
| `src/main.c` | Creates `game_context_t game_ctx` via `GameContext_InitDefault()`; uses `GameContext_Identity()` for save path |

### Filesystem safety

`GameIdentity_Valid()` now rejects:
- Path separators (`/`, `\`) in `game_id` and `prefs_id`
- Traversal sequences (`..`) in `game_id` and `prefs_id`

### Preserved behaviour

All default identity values unchanged. Window title, screenshot path, and save path remain identical when using the default context. Existing tests pass without modification.

## Step 3 corrections (review)

1. **Context initialized before SDL video startup**: `GameContext_InitDefault(&game_ctx)` now runs before `VL_StartupWithContext(&game_ctx)` in `main.c`.
2. **Consistent context propagation**: `VL_StartupWithContext()` stores the active context in `vl_active_context`; `VL_Screenshot()` uses it; `VL_ScreenshotWithContext()` updates it. `main.c` uses `GameContext_Identity()` for save path.
3. **No silent fallback**: `VL_StartupWithContext()` and `VL_ScreenshotWithContext()` return `false` when given an invalid/NULL context instead of falling back to the default identity.
4. **Legacy default path preserved**: `VL_Startup()` uses a static `game_context_t` initialized with the default identity, ensuring `vl_active_context` remains valid for the process lifetime. `VL_Screenshot()` uses `vl_active_context`. All default identity values unchanged.

5. **Ownership/lifetime contract**: Documented in `game_context.h` and `game_identity.h`. Caller owns identity memory; engine stores const pointers; strings must remain valid for context lifetime.
6. **Duplicate string.h include**: Removed from `game_identity.c`.
7. **Focused tests added**: Context propagation, invalid-context rejection, unsafe path rejection, lifetime expectations.
8. **Regression**: `game_identity_tests` pass; validation runner `R1.3` passes. Full R0 regression not rerun in this step (no simulation/renderer/format changes).
