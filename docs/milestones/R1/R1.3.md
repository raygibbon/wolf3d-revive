## Implemented boundary

### Game identity

`src/engine/game_identity.h` and `.c` define an SDL-free
`game_identity_t` with process-lifetime default values:

- `game_id = "wolf3d-revive"`;
- `display_title = "Wolf3D Revive"`; and
- `prefs_id = "wolf3d-revive"`.

`GameIdentity_Valid()` requires nonempty fields and rejects path separators and
`..` in filesystem identifiers. Alternative identities are accepted without
changing the default identity. Callers own alternative identity storage and
strings; returned pointers are borrowed.

### Application context

`src/engine/game_context.h` and `.c` define `game_context_t`, holding a borrowed
`const game_identity_t *`. `GameContext_InitDefault()` and `GameContext_Init()`
validate before publishing the pointer. `GameContext_Identity()` returns NULL
for invalid contexts. The context does not copy or free identity storage.

`src/main.c` initializes the default context before SDL startup and uses its
`prefs_id` for the application preference path.

### SDL platform behavior

`VL_StartupWithContext()` validates its context, creates the window using the
selected title, and publishes the active context only after complete successful
startup. Failure and `VL_Shutdown()` clear the active context.

`VL_Startup()` owns a static default context and delegates to the context-aware
function. `VL_Screenshot()` uses the active startup context.
`VL_ScreenshotWithContext()` uses the supplied context for that call only and
does **not** change the active context. NULL/invalid contexts fail rather than
falling back silently.

Default identity strings and default preference destinations are unchanged.

## Platform-test correction

The former screenshot override assertion only called `GameContext_Valid()` on
the original context. That could not observe or detect mutation of SDL video's
internal active-context pointer.

`tests/context_platform_tests.c` now exercises observable behavior:

1. Start SDL dummy/software video with an `alt-game` context.
2. Resolve `alt-game` and `override` preference directories through
   `SDL_GetPrefPath()` and verify both are under the caller-supplied temporary
   preference root.
3. Verify neither directory initially contains a screenshot.
4. Call `VL_ScreenshotWithContext(override)` and require exactly one nonfailed
   write under `override`, with none under `alt-game`.
5. Call `VL_Screenshot()` and require exactly one screenshot under `alt-game`
   while the `override` count remains one.

The Python wrapper sets `XDG_DATA_HOME` to a new `TemporaryDirectory`, checks
that generated BMPs are nonempty, expects three default, one alternative and
one override screenshot, and confirms the temporary tree is removed after the
test. The test does not write to the user's real preference directory.

SDL result reporting is explicit:

- a complete static library and headers are both required;
- direct unittest execution reports a missing SDK using `SkipTest`;
- the mandatory validation runner now requires both artifacts and reports an
  incomplete SDK as `NOT RUN`, which fails the selected mandatory gate;
- compile errors, SDL startup/capture failures, wrong destinations, unexpected
  counts and cleanup failures are unittest failures, not skips; and
- `tests/test_validation_runner.py` covers the incomplete-SDK `NOT RUN` path.
